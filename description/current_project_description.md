# Описание текущего состояния проекта CinemaAbyss

## Обзор проекта

Проект CinemaAbyss представляет собой систему стримингового сервиса, которая находится в процессе рефакторинга с монолитной архитектуры на микросервисную. Проект демонстрирует реализацию паттерна Strangler Fig для постепенного перехода между архитектурами.

## Текущая архитектура

### 1. Монолит (src/monolith/)

**Реализация:** Полнофункциональное Go-приложение на порту 8080

**Функциональность:**

- Управление пользователями (CRUD операции)
- Обработка метаданных фильмов
- Управление платежами
- Управление подписками
- Health check endpoint

**Технические детали:**

- Использует PostgreSQL для хранения данных
- REST API с эндпоинтами:
  - `/health` - проверка работоспособности
  - `/api/users` - управление пользователями
  - `/api/movies` - управление фильмами
  - `/api/payments` - управление платежами
  - `/api/subscriptions` - управление подписками

**Файлы:**

- `main.go` (483 строки) - основная логика приложения
- `Dockerfile` - контейнеризация
- `go.mod/go.sum` - зависимости Go

### 2. Микросервис Movies (src/microservices/movies/)

**Реализация:** Выделенный Go-сервис на порту 8081

**Функциональность:**

- Управление метаданными фильмов
- Получение списка всех фильмов
- Получение фильма по ID
- Создание новых фильмов
- Health check endpoint

**Технические детали:**

- Отдельная база данных PostgreSQL
- REST API с эндпоинтами:
  - `/api/movies/health` - проверка работоспособности
  - `/api/movies` - CRUD операции с фильмами

**Файлы:**

- `main.go` (198 строк) - логика микросервиса
- `Dockerfile` - контейнеризация
- `go.mod/go.sum` - зависимости Go

### 3. Микросервис Events (src/microservices/events/)

**Реализация:** Сервис для обработки событий через Kafka

**Функциональность:**

- Публикация событий в Kafka
- Обработка событий пользователей, фильмов и платежей
- Интеграция с Apache Kafka

**Статус:** Директория существует, но код не реализован (только .gitkeep)

### 4. Прокси-сервис (src/microservices/proxy/)

**Реализация:** API Gateway для реализации паттерна Strangler Fig

**Функциональность:**

- Маршрутизация запросов между монолитом и микросервисами
- Постепенное переключение трафика
- Feature flag для контроля миграции

**Статус:** Директория существует, но код не реализован (только .gitkeep)

## Инфраструктура

### База данных (src/database/)

**PostgreSQL:**

- Файл инициализации: `init.sql`
- Схема включает таблицы для пользователей, фильмов, платежей и подписок

### Контейнеризация (docker-compose.yml)

**Сервисы:**

- **PostgreSQL** (порт 5432) - основная база данных
- **ZooKeeper** (порт 2181) - координация Kafka
- **Kafka** (порт 9092) - брокер сообщений
- **Monolith** (порт 8080) - основное приложение
- **Movies Service** (порт 8081) - микросервис фильмов
- **Events Service** (порт 8082) - микросервис событий
- **Proxy Service** (порт 8000) - API Gateway
- **Kafka UI** (порт 8090) - веб-интерфейс для мониторинга Kafka

**Конфигурация Strangler Fig:**

- `GRADUAL_MIGRATION: "true"`
- `MOVIES_MIGRATION_PERCENT: "50"` (50% трафика идет в микросервис)

### Kubernetes (src/kubernetes/)

**Манифесты:**

- `namespace.yaml` - пространство имен cinemaabyss
- `postgres.yaml` - развертывание PostgreSQL
- `monolith.yaml` - развертывание монолита
- `movies-service.yaml` - развертывание микросервиса фильмов
- `events-service.yaml` - пустой файл (не реализован)
- `proxy-service.yaml` - пустой файл (не реализован)
- `ingress.yaml` - входящий трафик
- `configmap.yaml` - конфигурация системы

**Helm Charts (src/kubernetes/helm/):**

- Полный набор шаблонов для развертывания
- Включает все сервисы, базу данных и Kafka
- Конфигурируемые значения в `values.yaml`

### CI/CD (.github/workflows/)

**GitHub Actions:**

- `docker-build-push.yml` - сборка и публикация Docker образов
- `api-tests.yml` - тестирование API

**Автоматизация:**

- Сборка образов при push в main ветку
- Публикация в GitHub Container Registry
- Поддержка тегов и версионирования

## Тестирование (tests/postman/)

**Postman Collection:**

- `CinemaAbyss.postman_collection.json` - полный набор тестов
- Покрывает все сервисы и эндпоинты
- Поддержка различных окружений (local, docker, kubernetes)

**Автоматизация тестов:**

- `run-tests.js` - Node.js скрипт для запуска тестов
- `run-tests.sh` - shell скрипт для запуска тестов
- Интеграция с Newman для CI/CD

## Архитектурные особенности

### Паттерн Strangler Fig

- Конфигурация через переменные окружения
- Процентное распределение трафика
- Возможность постепенной миграции без простоя

### Микросервисная архитектура

- Разделение по доменам (фильмы, события, пользователи)
- Независимое развертывание сервисов
- Общая база данных (пока)

### Event-Driven Architecture

- Kafka для асинхронной коммуникации
- Топики для различных типов событий
- Расширяемая система событий

## Технический стек

- **Backend:** Go (Golang)
- **База данных:** PostgreSQL
- **Сообщения:** Apache Kafka + ZooKeeper
- **Контейнеризация:** Docker + Docker Compose
- **Оркестрация:** Kubernetes
- **Управление конфигурацией:** Helm
- **CI/CD:** GitHub Actions
- **Тестирование:** Postman + Newman
- **Мониторинг:** Kafka UI
